Contribute to the library

Four routes. None requires an AuthorID before you start; persistent private threads need a login.

Submit or revise research

Upload your manuscript or supply a DOI; review the prepared record; submit it to the seven admission gates. Accepted work is registered with a receipt.

Upload research

Suggest an external source

Point the library at a work that should be a source record. A source-only suggestion is never counted as your authored research.

Suggest a source

Propose a connection or challenge

Propose a typed relation between records with the evidence that supports it. Disagreement is an ordinary relation, never an admission failure.

Propose a relation

Ask a contribution question

Unsure which route applies? Ask; the thread keeps questions, source pointers, responses, and resolution state.

Ask a question

What admission means

{{ ADMISSION_BOUNDARY }} Outcomes are exactly ACCEPTED, RETURNED_FOR_REPAIR (not a rejection: the receipt lists the exact repair), and REJECTED (an evaluable contract violation; the receipt states the resubmission route). Every author, including the founder, meets the same gates.

Direct repository route

Experienced contributors may work in a Codespace or clone instead. Both routes share the same schemas, taxonomies, admission engine, identifier reservations, receipts, and preservation rules. Steps: reserve identifiers with python -m validators.reserve, search for duplicate work, prepare source and record files, evaluate with python -m validators.admit FILE --write (which stores the receipt, the exact submission snapshot, and the execution manifest), register only ACCEPTED work with --register, run python -m validators.validate, regenerate the projection with python -m validators.build_site, and open a pull request. See docs/PORTAL_CONTRIBUTING.md in the repository.
